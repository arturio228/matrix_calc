# Лабораторная работа 3 для Windows

Калькулятор матриц на C++17, вариант 8: `matrix_fill(Matrix m, double value)` заполняет существующую матрицу константой. Основная среда — Windows 11, Visual Studio Code и LLVM MinGW Clang. Код также собирается MSVC; CI отдельно проверяет Windows и Linux.

## Структура

- `include`, `src` — интерфейс, реализация и демонстрация.
- `tests` — 28 Google Test проверок и один автономный smoke из пяти групп сценариев.
- `scripts` — сборка, тесты, запуск и Doxygen из PowerShell.
- `.vscode` — задачи VS Code и запуск CodeLLDB.
- `CMakeLists.txt`, `CMakePresets.json` — C++17 и генераторы Windows.
- `Dockerfile`, `.github/workflows/ci.yml` — контейнер и автоматические проверки.

## Сборка и запуск Windows

Откройте папку `matrix_calculator` в Visual Studio Code. `Ctrl+Shift+B` запускает задачу `build`. Задачи `run`, `test`, `docs` доступны через Terminal → Run Task. Для отладки F5 нужно расширение CodeLLDB; для сборки оно не требуется.

Из PowerShell в корне проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\test.ps1 -NoBuild
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run.ps1 -NoBuild
```

`-ExecutionPolicy Bypass` действует только в дочернем процессе, исполняющем проверенный локальный сценарий; настройки политики Windows не меняются. Сценарии записаны в UTF-8 с BOM, совместимом с Windows PowerShell 5.1. Вывод переводится в UTF-8.

Сценарий ищет CMake, LLVM MinGW и `mingw32-make` в PATH или среди локальных переносных инструментов комплекта. В текущей рабочей папке он также распознает компилятор из соседнего семинара 7. При переносе проекта на другой компьютер укажите инструменты явно:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Compiler C:\Tools\llvm-mingw\bin\clang++.exe -CMake C:\Tools\cmake\bin\cmake.exe
```

Необходимы CMake 3.20 или новее и компилятор C++17. Если исходники Google Test доступны в `../_work/tools/googletest`, используются они. Иначе CMake находит установленный пакет или скачивает Google Test 1.15.2. Первый сетевой запуск требует соединения с GitHub.

Для независимого MSVC-варианта установите Visual Studio 2022 Build Tools с компонентами C++ и Windows SDK:

```powershell
cmake --preset windows-msvc
cmake --build --preset windows-msvc
ctest --preset windows-msvc
.\build-msvc\Debug\matrix_calculator.exe
```

MSVC использует `/W4 /WX /utf-8`, Clang — `-Wall -Wextra -Wpedantic -Werror`. Обычная Windows-сборка связывает runtime статически. Для LLVM MinGW выбран генератор `MinGW Makefiles`; пути инструментов сокращаются через Windows API, если в них есть кириллица. Исходники не копируются и не изменяются сборкой.

## Проверка AddressSanitizer

Сборка с инструментированием обращений к памяти отделена в `build-asan`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Asan
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\test.ps1 -Asan -NoBuild
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run.ps1 -Asan -NoBuild
```

В этом режиме используется `-fsanitize=address -fno-omit-frame-pointer`, статическая линковка отключена, а DLL runtime добавлена в PATH процесса. `detect_leaks=0` учитывает отсутствие LeakSanitizer для Windows: ASan проверяет обращения к памяти, а отдельный Valgrind в Linux проверяет утечки. Наличие команды не заменяет фактический успешный запуск; результаты сохранены в материалах проверки.

## Ошибки и владение памятью

Единый способ обработки ошибок — исключения: `std::invalid_argument` для неверных размеров, nullptr и неконечных значений; `std::overflow_error` для переполнения арифметики; `std::bad_alloc` при нехватке памяти. `main` печатает сообщение и возвращает код 1. При частичном выделении и при исключениях внутри вычисления память результата освобождается.

`Matrix` хранит `double**`, `rows`, `cols`, как требует методичка. Возвращаемая матрица имеет одного владельца. Присваивание структуры копирует указатели, но не данные. Нельзя освобождать обе копии или обращаться к ним после освобождения. `free_matrix(Matrix m)` принимает структуру по значению и не обнуляет оригинал. Правильное завершение владения:

```cpp
matrix::free_matrix(m);
m = {};
```

Повторное освобождение уже пустой структуры безопасно. Размер реального массива указателей и строк должен соответствовать размерам структуры; переносимый C++ не определяет длину памяти по произвольному указателю. `matrix_from_array` требует массив минимум из `rows * cols` элементов.

`matrix_fill` сначала проверяет все указатели строк и конечность константы, затем записывает ее без нового выделения. Прежние элементы, включая NaN, могут быть заменены. Сложность O(rows × cols), дополнительная память O(1). Для сложения и умножения исходные матрицы сохраняются. Умножение идет циклом i, k, j. `print_matrix` сокращает большие матрицы, сохраняя первые и последние 5 строк и 4 столбца, и печатает размер.

## Проверяемые сценарии

- Создание 3×4 с нулями, минимальная матрица 1×1, нулевые и отрицательные размеры.
- Копирование массива независимо от оригинала, nullptr и NaN/Inf.
- Сложение, прямоугольное умножение 2×3 на 3×2, строка на столбец, несовместимые размеры.
- Пустая структура, nullptr строки, безопасное освобождение пустой структуры.
- Транспонирование прямоугольной матрицы и двойное транспонирование.
- Вариант 8: заполнение 2.5, нулем и отрицательным числом, сохранение адресов и размера, отказ от NaN/Inf без изменения данных.
- Переполнение сложения и умножения, вывод большой матрицы с последним элементом.
- Интеграция заполнения, транспонирования, умножения и сложения.

Автономный smoke повторяет пять групп сценариев и работает также при определенном `NDEBUG`.

## Docker и CI

Dockerfile собирает приложение и тесты на Ubuntu 22.04, затем переносит приложение в отдельный runtime-образ. На Windows эти Linux-контейнеры можно запускать в Docker Desktop с Linux backend. Сам C++ проект не требует Docker для нативной сборки.

```powershell
docker build -t matrix-calculator .
docker run --rm matrix-calculator
```

GitHub Actions содержит два задания. `Windows MSVC build and tests` собирает `.exe`, выполняет все проверки и сохраняет Windows-артефакты. `Linux Valgrind Doxygen and Docker` проверяет стиль, сборку, CTest, память приложения и тестов, документацию, сборку и запуск контейнера. Все значимые команды сохраняют логи в артефактах workflow. Это CI с доставкой артефактов; публикация Docker-образа и развертывание не настроены.

Valgrind работает в Linux-задании и проверяет те же исходники; его результат не следует называть нативным запуском Windows. Достоверные логи и статус прогонов входят в материалы отчета после реального выполнения workflow.
